Agent Harness简述

Posted on 2026-11-10 Views: Word count in article: 1.4k Reading time ≈ 5 mins.

参考文章：https://www.langchain.com/blog/the-anatomy-of-an-agent-harness

Harness定义

Agent = Model + Harness。If you’re not the model, you’re the harness.

一个模型，你给一个确定的输入，模型会给你一个概率性的输出。从工程视角来看，这个模型做的是语义方面的工作，它本身是无状态的，不能直接操作外部工具，也没有反馈循环以及执行约束。模型相当于大脑，当你要利用模型去与外部世界交互，你就需要给模型提供“手脚”和“约束”。在一个agent里，除了模型外，其他的都属于harness。

harness包含以下内容：

  • 系统提示词

  • tools、skills、mcps以及其相关描述

  • 基础设施（例如文件系统、沙箱等）

  • 编排逻辑

  • 用来确保执行确定性的hooks和中间件（如lint checks、上下文压缩等）

下文将阐述本人的个人理解，即，为什么harness的设计里会包含这些结构。

设计问题与解决方案

当你想利用模型设计一个工程agent时，可能会遇到一些问题。一下将阐述遇到的问题以及将对应的解决方案。

问题 解决方案举例 详述
对于单个提问，模型的回答如何能更准确？ 系统提示词Prompt Engineering 约束角色、领域视角、思考规范以及安全边界防护
模型的一次输入输出解决不了问题，如何解决？ 编排逻辑 例如ReAct，Plan-and-Execute等
如何与外界进行外部交互，比如修改代码？ tools 工具 harness来调用和执行工具。harness向模型暴露工具的说明，模型告诉harness调用哪些工具、参数是什么，harness来进行执行。tools、skills、mcps都是属于工具类型。
除了人为前置提供工具实现，有一种实现方案是让模型自己设计工具代码（bash+code，general purpose tool）。这样开放度会高一点，但是同时需要注意权限安全问题。
直接在本机执行未知代码是存在风险的，如何解决风险问题？ sandbox 沙箱 利用沙箱来运行代码等，从而实现安全隔离。也可以实现水平扩展，从而承接高负载的agent运作。
如果让模型持续学习？两方面：（1）如何在多次会话之间积累经验教训（2）新知识 context inject上下文注入 1. 利用文件系统将经验教训持久化。某次会话将其获取的知识持久化存储下来，后续会话将其重新注入到上下文中
2. 新知识：利用网络搜索工具或者mcp工具来获取新知识，通过上下文注入给模型。
由于注入的上下文过多，模型在进行推理和完成任务时的表现会变差，怎么办？即，上下文腐化（context rot) context engineering 上下文工程 1. 压缩（compaction）：在上下文窗口内容快满了的时候，将上下文内容重写为精简摘要后重新填充至上下文窗口。缺点是可能会造成信息丢失。
2. skills：渐进式披露（progressive disclosure）。如果将大量工具的完整信息全部加载到上下文里，可能会撑爆上下文，影响模型注意力。skills就是只将工具的极小部分重要信息加载到上下文里，后续模型选择工具后，再逐渐披露该工具的具体内容
 3. context offloading：将工具等的输出等大型信息转移到文件系统，上下文中保留相关索引和摘要。等到模型再需要的时候，再进行加载
长周期自动化执行时，当其中一步出错时，后续步骤可能会越来越错。如何解决差以毫厘，谬以千里的问题？ planning and self-verification规划和自我验证 1. planning：模型将目标拆解为一系列步骤，加上todo list。
2. 每次步骤执行后，通过自我验证，来保证本次结论的正确性。可以借助hooks来运行测试用例，也可以借助其他模型进行判断，如果遇到报错，把报错信息返回给模型让模型进行自我修正。通过建立反馈来提高每一步的正确性。
长周期自动化执行过程中，如果出现异常stop了怎么办？多个agent通过什么协作？ Ralph Loops，File  systems + git 1. Ralph Loops：通过hook拦截模型给的异常退出信息，将上下文信息重新注入崭新的上下文窗口，强制模型完成目标。
2. 文件系统和git：文件系统持久化agent产生的重要知识，实现共享。git能够让agent了解最新进展以及历史记录。

总结

模型起到大脑的作用，手脚和约束需要通过harness工程来进行实现。读了一些文章，本人又产生了新的问题，LangChain的Harness优化能够agent跑分更高是做了些什么？Claude Code Harness具体是怎么设计的？DeepSeek的“一切皆可插件化”的Agent设计思想具体是什么样的？workflow和agent如何选型？agent编排如何选型？上下文工程现在有哪些流行通用方案？这些设计有什么优缺点？问题太多了，后续基于这些问题来学习。
